# Route the current request without reviving an old commercial topic

November 23, 2026. Draft work for #107 and #103; neither issue is complete or released by this branch.

The real-thread audit identified two connected routing defects. `charged` always selected the financial lane, including a physical battery predicate. The handler also classified the title, current request and every owned historical message as one string. Any old financial keyword could therefore override a later correction. A correct technical understanding could not unlock that inherited financial route, so the answer/review stages were skipped.

`requestRouting.js` now owns subject selection before the existing planner. A recognized current subject controls. An unknown standalone question stays unknown for understanding rather than borrowing an old billing lock. For bounded elliptical follow-ups, only the newest classifiable customer-owned statement supplies the subject; the owner's title is a last fallback. Earlier facts, attempts and scoped staff/bot notes still reach planning, retrieval, answer and review as conversation. The change neither erases an outstanding case nor turns history into authoritative product evidence.

The existing router distinguishes a closed physical `charged` predicate from a transaction. A financial complement or a separate transaction occurrence remains protected. An explicit local denial of a payment label does not create another payment request. Battery wording without a phone/app subject can select the device lane; an explicit phone/app subject retains its ordinary route. These English lexical rules are deliberately bounded, not general multilingual intent understanding.

Understanding may correct an inherited commercial route to a technical problem when the current request has no deterministic subject. An explicit current money or privacy request remains fenced even if the planner contradicts it. Shipping quotes retain their existing special handling. The existing planner instruction also distinguishes the latest goal from retained historical facts and completed actions, while preserving current multipart requests. No source ranking, provider, storage, private-data permission, case acceptance or delivery-state rule changes.
